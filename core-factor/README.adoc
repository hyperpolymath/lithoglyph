= Form.Runtime (Factor) — storage binding and ABI seam
:toc:

The Factor side of the Lithoglyph ABI: the vocabulary that binds a Factor
process to Form.Bridge, plus the tests that prove that seam holds.

== What lives here

`storage-backend.factor`::
  The pluggable storage layer. Two backends: `memory` (in-process, for tests)
  and `bridge` (persistent, via Form.Bridge over the C ABI). This is the
  surface the query language binds to.

`test-ffi.factor`::
  Drives the `storage-backend` vocabulary end to end.

`minimal-ffi-test.factor`::
  Loads `libbridge` directly and calls the version function — the narrowest
  possible check that the ABI is reachable at all.

Run both with `just test-factor`.

== What moved, and why

GQL — the Glyph Query Language — used to live here as `gql/gql.factor`,
`gql/lexer-tests.factor`, `gql/benchmarks.factor`, `gql/seam-tests.factor` and
`gql-c-api/gql-c-api.factor`. It is now developed in its own repo:

https://github.com/hyperpolymath/gnpl[hyperpolymath/gnpl] (`runtime/`)

The dependency runs one way and must stay that way. `gql.factor` declares
`USING: ... storage-backend ...` — the *language* reaches into the *core*, never
the reverse. Keeping the GQL files here would have made gnpl a build dependency
of lithoglyph and re-coupled two repos that were deliberately separated.

`seam-tests.factor` moved with them despite its name. It tests the GQL pipeline
(Parser -> Planner -> Executor -> Normalizer) and declares `USING: gql`; it does
not touch `alien` and never crossed the ABI. The seam this repo owns is
Factor <-> Form.Bridge, and the two files named above are what test it.

== Status

`storage-backend.factor` is implemented against Form.Bridge. The GQL grammar
specification (Q-GQL-POC-001) is tracked in gnpl, not here.
